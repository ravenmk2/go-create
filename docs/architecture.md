# 架构与关键设计

go-create：按工程规范生成 Go 项目骨架的初始化工具。本文档记录架构与关键设计决策及其理由。

## 架构分层

```txt
cmd/go-create/      程序入口，只做组装
internal/
├── template/       模板模型：加载（embed + 用户目录）、校验、when 求值、渲染
├── generate/       生成编排：参数校验 → 共用渲染 → 预览或写盘 → 后置动作（git init / go mod tidy）
├── cli/            cobra 命令：root（裸运行进向导）/ new（--set / --dry-run）/ list / show / upgrade
├── upgrade/        自更新：GitHub releases 查询 → 下载（重试/停滞检测）→ SHA256 校验 → 平台自替换
└── wizard/         交互向导：TTY 走 bubbletea 自绘 TUI（步骤指示器 + 实时摘要侧栏 + 前进/后退）；非 TTY 降级 huh accessible 模式
templates/          内置模板（cli / web / lib），embed 进二进制
```

数据流（两条收集途径汇入同一参数集）：

```txt
TUI 向导  ─┐
           ├─→ generate.Params ─→ template.Render ─→ 写盘 ─→ git init / go mod tidy
--set/--yes 参数 ─┘   （公共参数 + 模板选项）
```

## 关键设计决策

### 清单驱动的产物映射

每个模板 = `template.yaml` + `files/`（全部源文件）。`files` 清单逐条定义一个产物的完整映射：**源文件 → 是否渲染 → 内容分隔符 → 目标路径 → 生成条件**。不采用目录约定（如 render/ 与 static/ 分树）或后缀约定（.tmpl），因为清单是唯一事实来源，可 review、可校验，且目标路径与源路径解耦（dest 含变量，无法靠目录结构表达）。

### 双套分隔符分工

- **文件内容**：可配置分隔符，默认 `ecb`（`<% %>`，ASP.NET embedded code block 术语），备选 `go`（`{{ }}`）、`brackets`（`[[ ]]`）或自定义。理由：产物中高频出现 Go template 语法（goreleaser 的 `{{.Version}}`、GitHub Actions 的 `${{ }}`），若用 `{{ }}` 渲染则满屏转义（Helm 的教训）；换分隔符后这些内容零转义穿过
- **dest 路径**：固定 `{{ }}`，只放变量禁逻辑。dest 是 YAML 字符串、不落盘为真实文件名，不受 Windows 文件名禁用字符（`<>`）约束，与内容分隔符解耦

### 可靠性闭环

模板是可扩展点，扩展必然带来腐化风险，因此引擎内置多层校验：

1. **加载期**：YAML 严格模式（未知字段报错）；`schema` 版本校验（缺省 1，拒绝更高版本，为将来破坏性变更留门）；选项 schema 校验；when 表达式用 expr-lang **编译期校验**（引用未声明选项 key 直接报错）；清单 src 存在性检查
2. **生成期**：`files/` 下未列入清单的文件 → 警告；静态复制文件内容含分隔符 → 警告（疑似漏登记 render）；dest 必须是 `/` 分隔的规范相对文件路径，拒绝 `.`/`..` 路径段、反斜杠、卷名和空路径。文件与 LICENSE 均通过 `os.Root` 写入，阻止目标目录内的符号链接将写入引向项目之外
3. **自测矩阵**：`template.yaml` 的 `tests` 段声明代表性选项组合，go-create 自身 `go test` 逐组生成到临时目录并 `go build ./...` 验证产物可编译——模板扩展的护栏

### 向导 UI：bubbletea 自绘 + huh 降级

向导交互层用 bubbletea/lipgloss 自绘（步骤指示器、实时摘要侧栏、窗体布局），而非继续堆叠 huh 表单。理由：选项多了之后 huh 单组堆叠渲染会溢出终端；且需要步骤级前进/后退与全局状态可见性，自绘 Model 控制粒度更细。选项按描述文件的 `group` 字段分页，未分组的自动按每页 5 个分页。非 TTY 环境（管道/重定向）没有交互界面可用，降级为 huh accessible（纯文本逐行问答），huh 依赖仅为此保留。

视觉上问题、选项、值、必填提示、说明和操作按键均保持正常对比度；强调色采用高饱和青色，当前选项在浅色终端使用深青背景与白字，在深色终端使用亮青背景与深蓝文字，并保留焦点标记，已选项以实心圆或复选框及加粗区分。摘要标签使用同一青色，值加粗；开关以鲜明绿色 `✓ On` 或普通文字 `– Off` 区分，错误使用玫红色，边框使用对比更清晰的蓝灰色。深浅背景使用自适应配色，并以符号和字重支持无颜色环境。

界面最大为 116 列、32 行，宽屏水平居中；104 列起展示 36 列侧栏，72～103 列保留单栏外框，更窄或不足 20 行时使用无外框紧凑布局。侧栏显示固定顺序的项目概况和当前字段的说明，避免重复主区选项；窄屏将说明放回字段下方。实色高亮仅用于当前控件，侧栏用小标记提示关联字段。长模块路径保留首尾，其他概况长值尾部省略，完整值留在确认页。高度不足时截断说明并提示扩大窗口。不扩展模板 schema。

最终确认页取消侧栏，以全宽按 Project 和模板选项 `group` 展示配置，并列出实际覆盖文件；选择项显示可读标签，长值完整换行。Create/Cancel 固定在配置视口下方，有覆盖时改为 Overwrite & create 并默认选中 Cancel。首次进入从顶部显示，PgUp/PgDn 和鼠标滚轮独立滚动配置。按 E 打开分组选择器，可编辑命令行预填的公共参数，编辑完该页直接返回确认。提交前刷新覆盖列表；若冲突变化则再次展示并要求选择。无 TTY 的 huh 降级确认合并相同的覆盖信息，不再退出向导后另开确认框。

Tab/Shift+Tab 切换字段，Enter 前进或最终确认；Tab 在最终确认页不会提交。项目名和模块路径使用生成器共用校验，在离开字段时显示错误。短布尔选项的标题与 On/Off 控件共用一行，支持左右键；宽屏页头尽可能显示步骤名称及完成标记，放不下时回退为数字步骤。减少内部装饰分隔线，说明采用可读的次级颜色；底部操作提示自动换行，高度纳入视口计算。

### 生成进度与执行日志

`GenerateWithProgress` 按实际执行时序同步发出渲染、写入、Git 初始化、依赖整理四个阶段的结构化事件；原有 `Generate` 调用不传观察者，保持调用方式与结果兼容。事件包含运行、完成、跳过、警告和失败状态以及说明，不携带终端样式；CLI 在工作开始时显示步骤编号，结束时显示结果，依赖重试时补充尝试次数。生成器不依赖界面层，输出与生成逻辑分离。

TTY 使用与 TUI 一致的高饱和青色强调阶段编号、目录和后续命令，成功为鲜绿色，警告为亮黄色，失败为玫红色，配合符号区分状态。阶段标题和最终结果加粗；深色终端采用亮白标题与浅灰正文，浅色终端采用深色文字，避免继承终端较暗的默认前景色。重定向、`NO_COLOR` 或 `TERM=dumb` 使用普通文本。完成后汇总文件数、目录与阶段结果，并根据实际状态给出 `git init` / `go mod tidy` 补救命令。写盘等致命错误保留失败退出码，不打印成功；Git 和依赖整理失败继续保留项目并显示警告，显式禁用与已有 `.git` 显示跳过。

支持颜色的 TTY 在执行期间显示 spinner 和当前尝试的耗时。每次状态日志前停止并清除动画行，等待动画 goroutine 退出，保证输出不交错；重定向保留稳定的逐行日志。

### 生成预览与模板发现

`list` 只显示模板概览，`show <template>` 展示描述、默认值、可选值、约束和 `--set` 示例。`new --dry-run` 可以配合向导或 `--yes`；它与实际生成共用参数校验、模板渲染和 LICENSE 生成，只读取目标目录来标记覆盖冲突，不写文件、不执行 Git 或依赖命令。向导确认页复用同一预览。预览是检查时的快照，不锁定外部进程对目录的修改。

### 生成到非空目录

目标目录允许非空（支持"先 git init / clone 空仓库再生成"的场景）：交互向导在最终确认页列出实际覆盖文件并显式确认；`--yes` 视为已确认直接生成。生成期逐文件检测覆盖并输出 warning；目标目录已含 `.git` 时跳过 `git init`（避免无意义的 reinit）。后置动作（git init / go mod tidy）失败一律降级为 warning，不阻断生成；其中 go mod tidy 依赖网络，内置 3 次线性退避重试以吸收代理/仓库的瞬时故障。

### 自更新（upgrade）

`go-create upgrade` 从 GitHub releases 自更新，纯标准库实现（不引 go-update 类框架）：

- **Resolve/Apply 分离**：先只拉 release 元数据做决策（dev 永远可升级、版本相等幂等、不主动降级、显式 `--version` 允许降级），用户确认后再下载执行；`--check` 只查不下载
- **可靠性**：下载带指数退避重试 + 停滞 watchdog（30s 无数据流入判定停滞可重试，慢速下载不受影响）；资产经 checksums.txt SHA256 校验后才允许替换；不做签名校验（留作后续增量）
- **平台自替换**：Unix 同目录临时文件复制完成后显式设为 `0755`，再 rename 原子覆盖，避免临时文件默认的 `0600` 权限导致升级后无法执行；Windows 运行中的 exe 不能覆盖但能 rename——旧文件改名 `.old` 再写入新文件（失败回滚），`.old` 留作备份、下次 upgrade 时清理
- 只支持 GitHub 源（主发布渠道），不做后台自动检查（只显式命令）

### web 模板的开发镜像发布

`docker_dev` 独立控制 `.github/workflows/docker-dev.yml`，默认开启，与正式镜像选项 `docker_image`、发布选项 `goreleaser` 解耦。`docker_dev || docker_image` 时生成 Dockerfile；开发镜像本身不触发 GoReleaser 配置生成。

开发工作流在 `master/main/dev/develop` 分支推送或手动触发时，先 lint、vet、test，再由 Actions 构建前端（启用 embed 时调用 `scripts/build-web.sh`）和 `CGO_ENABLED=0` 的 Linux amd64 二进制，最后复用只打包二进制的 Dockerfile 推送 GHCR。这样开发与正式发布共用运行时镜像定义，无需维护另一份源码构建 Dockerfile。镜像路径取运行时 `github.repository` 并转小写，不依赖模块路径。

各分支共用 `:dev` 标签，因此工作流使用不含分支名的固定 concurrency group，`cancel-in-progress: false` 让当前运行完成后再执行后续运行，防止多个分支同时发布。GitHub 默认仅保留一个待运行任务，更新的待运行任务会替换旧的；不承诺每次推送均发布或 FIFO 顺序。现阶段保留与 `test.yml` 重复的检查。

### 依赖版本不 pin

模板的 go.mod 只写 `module` + `go` 指令；框架依赖仅体现在源码 import 中，生成后由 `go mod tidy` 拉取最新兼容版本。模板零版本腐化维护；可复现性由生成项目自身提交的 go.sum 兜底。无网络时降级为提示手动执行。

### 选项类型系统

`type` 采用 Jenkins 风格命名：`boolean`（确认框→bool）/ `string`（文本输入→string）/ `choice`（单选→string）/ `multichoice`（多选→[]string）。类型同时决定表单形态与数据类型，两者一一对应无需分开声明。选项级条件（选项间依赖）暂不支持，schema 预留。

字符串 `pattern` 在模板层统一校验，覆盖默认值、命令行和两种向导；空字符串仍视为可省略。向导切换模板时清除原模板专属选项，保留新模板也声明的共用选项，确保最终生成参数与界面一致。

### 公共参数 vs 模板选项

`name`/`module`/`license`/`holder` 等所有模板共享的参数内置在工具中，不在描述文件重复声明。LICENSE 文本（MIT/Apache-2.0/GPL-3.0）内置工具，模板不感知。

项目名转为小写并去除标点后，必须是合法 Go 标识符且不能为 `_`；数字开头和 Go 关键字会在写盘前被拒绝，向导使用相同转换规则。

### 模板优先级

内置模板 embed 进二进制；用户目录 `~/.config/go-create/templates/`（全平台统一）下的同名模板完全覆盖内置。新增模板 = 新增一个目录，不改代码。

## 边界（明确不做）

- 不生成前端脚手架（embed_frontend 仅 Go 侧骨架）
- 不做 git commit（只 git init）
- 不做模板版本管理、远程模板仓库
